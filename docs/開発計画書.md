### 1.2 合成ルールの言い換え（要確認）

要件R3の3つのルールは、次の **1つの原則** にまとめられる。

> **各画素について「飽和していない（安全マージン込み）フレームのうち、最も明るいフレーム」を使う。**

この原則から、要件のルールはすべて出てくる。

- **ハイライト**：明るいフレームは飽和している。飽和していないフレームのうち最も明るいもの、つまり「短いが短すぎない」フレームが選ばれる。必要以上に暗いフレームは選ばれない。
- **中間調**：飽和せず、かつ最も露光量の多い（S/N比が最良の）フレームが選ばれる。これが「ほど良い」フレームにあたる。
- **シャドウ**：明るいフレームが飽和していないので、自動的に明るいフレームが選ばれる。暗いフレームのシャドウは使われない。

物理的な根拠は次のとおり。RAWは線形なので、露出比で正規化すれば各フレームの値は同じシーン輝度を表す。そのうえでショットノイズと読み出しノイズを考えると、**露光量が最大のフレームがS/N比最良** になる。よって上の原則は画質面で最適な選択と一致する。

> ✅ **この解釈でよいか、ユーザー確認をお願いしたい。**
> 補足：「最も明るい非飽和フレーム1枚を選ぶ」（選択型）と「非飽和フレームをS/N比で重み付け平均する」（平均型）の2方式が考えられる。平均型はノイズがやや減るが、被写体ブレやゴーストに弱い。既定は選択型とし、平均型はオプションにする案とする（§5.4）。

## 3. RAW入力（R1）

### 3.1 デコーダ構成

| 経路 | 役割 |
|------|------|

| **DNG入力**（常時サポート） | DNG SDKで読む。LibRawが未対応の新機種でも、ユーザーが Adobe DNG Converter でDNG化すれば必ず読める。**新機種対応の確実な逃げ道** |
| **Adobe DNG Converter 連携**（任意） | インストール済みなら、未対応RAWを自動でDNG化してから読み込む（CLI呼び出し）。※App Storeのサンドボックスとは両立しにくい（§10） |

- 起動時に「このRAWはLibRawで読めない → DNG Converterで変換してください／自動変換しますか？」と案内する。

| 種類 | 例 | 合成単位 | 出力形式 |
|------|----|----------|----------|
| Bayer | 大多数の機種 | 2×2ブロック | CFA DNG |
| X-Trans | Fujifilm | 6×6周期（判定は3×3または6×6ブロック） | CFA DNG |
| Foveon / LinearRaw | Sigma、一部DNG | 画素単位（3ch） | LinearRaw DNG |
| モノクロセンサー | Leica M Monochrom 等 | 画素単位（1ch） | モノクロDNG |

### 3.3 読み込み時の検査

- 同一ボディ・同一レンズ・同一解像度・同一ISO（異なる場合は警告）であることを確認する。
- 露出情報（ExposureTime、FNumber、ISO、ExposureBiasValue）を取得し、露出順に並べる。
- 黒レベルを取得する。機種によってはフレームごと・チャンネルごとの値や、オプティカルブラック領域からの推定値になる。
- 白レベル（WhiteLevel）とリニアライゼーションテーブルの有無を確認する。
- ブラケットの自動グルーピング：フォルダ一括読み込み時に、撮影時刻の近さと露出パターンからブラケットセットを推定する（後続フェーズ）。

## 4. 位置合わせ（R2）

### 4.1 モード

| モード | 用途 |
|--------|------|
| なし | 三脚固定。既定値にはせず、ユーザーが選ぶ |
| 自動 | 手持ち、三脚の微小なズレ |
| 手動 | 高輝度・低テクスチャで自動が失敗する場合。自動の結果を手動で微修正することもできる |

### 4.2 自動位置合わせ

1. **解析用プロキシの生成**
   - CFAを2×2などでビニングし、低解像度の線形輝度画像を作る。
   - 露出比で正規化し、全フレームを同じ明るさのスケールに揃える。
   - 飽和域と黒つぶれ域にはマスクをかける。
2. **チェーン方式で位置合わせする**
   - 極端に露出の離れたフレーム同士は、直接には合わせない。
   - 隣り合う露出同士（-2EV↔0EV、0EV↔+2EV …）でペアごとに推定し、変換を合成して基準フレームへ繋ぐ。
   - 各ペアでは、両方のフレームで有効な画素だけを使う。
3. **推定手法**（段階的に試す）
   - 粗い推定：MTB（Median Threshold Bitmap, Ward法）。露出差に強い並進推定に使う。
   - 精密化：特徴点（AKAZE/ORB等）＋RANSAC、またはECC（強度ベースの最適化）で行う。どちらも勾配やlog輝度の上で計算する。
4. **変換モデル**：並進 / ユークリッド（並進＋回転） / 相似 / 射影（ホモグラフィ）から選べる。既定は「ユークリッド」とし、望遠や広角の手持ちでは射影を推奨する。
5. **品質指標**：残差（位置合わせ後の差分）をヒートマップで表示する。閾値を超えたら手動モードを提案する。

### 4.3 手動位置合わせ

- 基準フレームと対象フレームの **差分表示 / オニオンスキン（半透明重ね） / A-B切替（フリッカー） / 分割表示** を用意する。
- 表示時は露出を正規化し、比較しやすい明るさで見せる。
- 操作は次のとおり。
  - ドラッグ、または矢印キーで並進する（1px / 0.1px 刻み）。
  - 回転（0.01°刻み）と拡大縮小。
  - **制御点指定**：両フレームで対応点を2点以上クリックし、変換を解く。高輝度で特徴の少ない場面でも、ユーザーが確実な対応点を指定できる。
- 手動での修正結果はプロジェクトファイルに保存する。

### 4.4 CFAを保ったまま位置合わせできるか（重要な制約）

CFA（モザイク）配列を壊さずに移動できるのは、**CFA周期の整数倍の並進（Bayerなら2px単位、X-Transなら6px単位）だけ** である。サブピクセル移動・回転・射影変換を行うと、色フィルタの位置がずれてモザイクが崩れる。

そこで、出力は2つのモードとする。

| 出力モード | 条件 | 方法 | 長所 | 短所 |
|-----------|------|------|------|------|
| **A: CFA DNG**（推奨・既定） | 位置合わせなし、またはCFA周期単位の並進のみ | モザイクのまま合成する | Lightroomのデモザイク・AIノイズ除去・強化（Enhance）の恩恵を受けられる【要検証】。RAWらしさが最大 | 手持ちの微小回転を補正できない |
| **A': CFA DNG（再モザイク）** | サブピクセル補正が必要 | CFAの色プレーンごとに補間・変換し、再びモザイク化する | CFAの形式を維持できる | 補間で解像感がわずかに落ちる。色ずれのリスクがある |
| **B: LinearRaw DNG** | 回転や射影変換が必要 | 各フレームを自前でデモザイク → 変換 → 合成し、カメラネイティブ色空間の線形3chで出力する | 位置合わせが最も正確 | デモザイクをLightroomに任せられない。AIノイズ除去が使えない可能性がある【要検証】 |

- A'とBのどちらを既定にするかは、Phase 0〜1の画質比較で決める。
- UIでは「位置合わせの結果、CFA DNGを維持できません。A'/Bのどちらで出力しますか？」と選択肢を示す。

### 4.5 基準フレームの扱い（レンズ補正との整合）

- **基準フレームは移動・トリミングしない**。他のフレームを基準フレームに合わせる。
  - 理由：レンズプロファイルの歪曲・周辺光量補正は、元の光学中心と画像寸法を前提にしている。基準がずれると補正が合わなくなる。
- 基準フレームは既定で中央露出（0EV）とし、ユーザーが変更できる。
- 位置合わせで生じる周辺の無効領域は、画素を切り取らずに **DefaultCropOrigin / DefaultCropSize（DNGタグ）** で隠す。無効画素は基準フレームの値で埋める。

## 5. HDR合成アルゴリズム（R3, R3a）

### 5.1 前処理（すべて線形RAW領域で行う）

1. 黒レベルを減算する（チャンネル別。フレームごとに値が違う場合にも対応）。
2. リニアライゼーションテーブルがあれば適用する。
3. フラットフィールドやデフェクトピクセルは、原則として手を加えない（Lightroomに任せる）。ただしホットピクセルが合成判定を乱す場合は判定側で除外する。

### 5.2 飽和閾値の決定

- センサーは白レベルの手前から非線形になる機種がある。そのため **飽和閾値 = WhiteLevel × 安全係数**（既定0.90〜0.95、機種別プリセットとユーザー調整に対応）とする。
- 閾値は、実データのヒストグラム上端を解析して機種別に自動推定する機能も持たせる。
- **判定はCFAブロック単位**：ブロック内のどれか1チャンネルでも閾値を超えたら、そのブロックは「飽和」とみなす。1チャンネルだけ飽和した状態で使うと、色かぶり（マゼンタハイライト等）の原因になるため。

### 5.3 露出比の推定（EXIFの値だけに頼らない）

- EXIF上の露出比（例：2EV = 4倍）は、実際にはシャッター精度・絞りの精度・フリッカーで数%ずれる。この **ずれが継ぎ目の主な原因** になる。
- 隣り合うフレーム間で、両方とも有効（非飽和・高S/N）な画素を集める。そのうえでロバスト回帰（外れ値に強い推定）で実測の比を求める。
  - チャンネル別に推定し、差が大きければ警告する（光源のフリッカー等の検出）。
  - 必要なら黒レベルのオフセット項も同時に推定する（`y = a·x + b`）。
- 推定した比を全フレームで連鎖させ、基準フレームのスケールに正規化する。

### 5.4 重みマップの生成

各フレーム *i* について、ブロックごとに次を行う。

1. **使用可能マスク** `U_i`：非飽和であり、かつ下限（ノイズフロアより十分上）を満たすこと。ただし最も明るいフレームでは下限を適用しない。
2. **選択型（既定）**：各位置で、`U_i` が真のフレームのうち最も露光量の多いものを選ぶ。これを `S_i`（one-hot）とする。
3. **平均型（オプション）**：`U_i` が真のフレームを、分散の逆数（≒露光量）で重み付けする。
4. 最暗フレームも飽和している位置（フレームの範囲を超えた光源など）は、最暗フレームの値をそのまま使い、「クリップ」フラグを立てる。

### 5.5 継ぎ目を滑らかにする（R3a）

継ぎ目が目立つ原因と、それぞれの対策は次のとおり。

| 原因 | 対策 |
|------|------|
| 露出比の推定誤差 | §5.3のデータ推定（最重要） |
| 黒レベルの誤差 | 正確な黒レベル処理と、オフセット推定 |
| 飽和手前の非線形性 | 安全係数付きの閾値（§5.2） |
| ノイズ量の差（暗いフレームの領域がざらつく） | 遷移帯を広く取ったフェザリング。平均型の併用 |
| レンズフレア・ゴーストの差 | 検出して警告。重みを局所的に調整 |
| 位置合わせの残差 | 残差の大きい領域は遷移を狭める、または単一フレームに固定 |

**重みの平滑化の手順**（ここが肝要）：

1. 合成マップ（どのフレームを使うか）を、低解像度プロキシの上で計算する。
2. **飽和画素に重みが漏れないようにする**：
   - まず、各フレームの使用可能領域 `U_i` を遷移幅の分だけ **収縮（erode）** する。
   - その後にぼかし（ガウシアン、またはエッジ保存のガイデッドフィルタ）をかける。
   - こうすれば、ぼけた重みが飽和画素に0より大きい値を持つことが **構造的に起こらない**。
3. 重みを正規化（総和1）し、フル解像度にアップサンプルして適用する。
   - **プロキシからの飽和の漏れを防ぐ**：
     - プロキシ用に飽和マスクを縮小するときは、平均ではなく **最大値プーリング** を使う。小さな鏡面反射や点光源が縮小で薄まり、「非飽和」と誤判定されるのを防ぐため。
     - さらに **フル解像度でもCFAブロック単位で飽和を判定する**。飽和ブロックの重みは強制的に 0 とし、残りのフレームで重みを正規化し直す（最終的な安全網）。
4. 遷移幅は「滑らかさ」スライダーで調整できるようにする（既定：画像の長辺の0.5〜1%程度）。
5. 線形領域でラプラシアンピラミッド合成を行うと、負値やハローが出やすい。このため既定は **重みマップの平滑化＋線形空間での重み付き和** とする。ピラミッド合成は比較実験の対象にとどめる。

### 5.6 ゴースト（動体）対策（後続フェーズ）

- 露出正規化後のフレーム間の不一致を検出する（ノイズモデルに基づき、期待されるばらつきを超えるものを抽出）。
- 不一致領域は単一フレーム（既定は基準フレーム、ユーザー選択も可）に固定する。
- 検出マスクの表示と、ブラシによる手動修正。

### 5.7 合成マップの可視化

- 各領域がどのフレーム由来かを色分けで重ねて表示する。
- 飽和・クリップ領域の警告表示。
- 遷移帯の表示（継ぎ目の確認用）。

## 6. 出力DNG仕様（R4, R5）

### 6.1 画像データ

| 項目 | 仕様 |
|------|------|
| 形式 | DNG 1.4以降。モード A/A' はCFA、モード B は LinearRaw |
| サンプル形式 | 浮動小数点（SampleFormat=3）。16bit（half）/ 24bit / 32bit を選べる。**既定は自動選択**：「ADCビット数＋ブラケット幅(EV) ≦ 約24」なら16bit、超えたら24/32bit（下記「ビット深度の注意」参照） |
| 圧縮 | Deflate＋浮動小数点プレディクタ（TIFF Predictor=3、およびDNG拡張のFloatingPointX2/X4系）【要検証：各プレディクタのLR/ACR対応状況】 |
| 値のスケール | 下記の案1・案2のどちらにするか【要検証】 |
| WhiteLevel | 採用したスケールに合わせて設定し直す（元の整数値は引き継がない）【要検証】 |
| DNGBackwardVersion | **1.4** とする。古いLR/ACRでも開けるよう、DNG 1.6/1.7で追加された機能（JPEG XL圧縮など）は使わない |
| タイル | タイル分割で格納する（例：256×256） |

**値のスケールと BaselineExposure（相互に依存するため一体で決める）**

| 案 | スケール | BaselineExposure | 前提・懸念 |
|----|----------|------------------|------------|
| 案1 | 基準フレームの白 = 1.0。ハイライトは 1.0 を超える値で保持する | 基準フレームの値を引き継ぐ | LR/ACRが浮動小数点DNGの1.0超の値をクリップしないことが前提【要検証】 |
| 案2 | 最暗フレームの飽和点 = 1.0（全データを0〜1に収める） | 基準フレームの値 ＋ log2(スケール係数) | HDRMergeやLightroom自身のHDR結合がこの方式に近いと思われる【要検証】 |

→ Phase 0 で、Lightroom の「写真を結合 → HDR」の出力DNGと、HDRMergeの出力DNGを実際に解析する。WhiteLevel、スケール、BaselineExposure、プレディクタ、ビット深度を調べて方式を決める。

**ビット深度の注意**：案2では、最も明るいフレームのADC 1段分の値が約 2^-(ADCビット数＋ブラケット幅EV) になる。half float（16bit）が表せる最小の刻み（非正規化数）は 2^-24 である。例えば14bitセンサーで±2EV×7枚（幅12EV）の場合、必要な刻みは 2^-26 となり、half では最暗部の階調がつぶれる。このため、ビット深度はブラケット構成に応じて自動で選ぶ。

### 6.2 RAW調整の余地を最大化するためのメタデータ（R5）

| タグ / 項目 | 方針 |
|-------------|------|
| **UniqueCameraModel** | Adobe DNG Converterの出力と **完全一致** させる。一致しないと、LightroomのカメラプロファイルのAdobe Standard / Camera Matching 等が出ない【要検証】 |
| Make / Model / 各種EXIF | 基準フレームから全部コピーする |
| ColorMatrix1/2、ForwardMatrix1/2、CalibrationIlluminant1/2、CameraCalibration | カメラ由来の値を入れる。ソースはLibRawの係数表、または入力DNG。可能なら DNG Converter の出力値と一致させる |
| AsShotNeutral | ホワイトバランスは焼き込まず、撮影時の値を保持する |
| **BaselineExposure** | 基準フレームと同じ見た目で開くよう調整する。値の決め方はスケール方式による（§6.1 案1/案2） |
| **BlackLevel / LinearizationTable** | 合成時に黒レベル減算と線形化を **適用済み** なので、BlackLevel は 0 とし、LinearizationTable は出力しない（二重適用の防止）。WhiteLevel も新しいスケールに合わせて設定し直す |
| **OpcodeList1/2（値の変換系）** | MapTable や MapPolynomial など値を変換するOpcodeは、元の整数レンジを前提にしている。そのため引き継ぐ前に内容を精査し、必要なら変換または除外する。OpcodeList3の幾何補正・周辺光量補正はそのまま引き継いでよい |
| AnalogBalance | 入力にあれば引き継ぐ |
| NoiseProfile | 合成後は画素ごとにノイズ量が異なる。どう扱うか（基準フレーム値／最良値／省略）は比較して決める【要検証：LRのノイズ除去への影響】 |
| DefaultCrop / ActiveArea / DefaultScale | 基準フレームに合わせる。位置合わせによる無効域は DefaultCrop で隠す（§4.5） |
| プレビュー / サムネイル | 簡易現像したJPEGプレビューとサムネイルを埋め込む（Finderやカタログでの表示用） |
| DNGPrivateData / MakerNote | 元のメーカーノートを保全する（§6.3 b） |
| OriginalRawFileName / 独自XMP | 元の複数ファイル名、露出値、合成パラメータを記録する（再現性と追跡のため） |

### 6.3 「レンズプロファイルの埋め込み」の具体化（R4）

「埋め込み」には **性質の異なる4つの仕組み** があり、すべて実装する。

| # | 仕組み | 内容 | 効果 |
|---|--------|------|------|
| a | **EXIFのレンズ情報** | LensModel、LensMake、LensInfo、LensSerialNumber、FocalLength、FNumber、FocalLengthIn35mmFilm、撮影距離（あれば）を正確にコピーする | LR/ACRが **自社のレンズプロファイルを自動で認識・適用** する（最も重要） |
| b | **メーカーノート** | MakerNoteをDNGPrivateData経由で保全する（オフセット修正込み） | メーカー固有のレンズIDや補正情報が失われない。LRのレンズ識別に使われるケースがある【要検証】 |
| c | **DNG OpcodeList**（WarpRectilinear / FixVignetteRadial / GainMap 等） | カメラ内蔵のレンズ補正データ（主にミラーレス機）を、DNG Converterと同様にOpcodeとして格納する。入力がDNGなら、そのOpcodeListをそのまま引き継ぐ | LRが「組み込みレンズプロファイル」として強制的に適用する。**CFA合成でも幾何の前提が崩れないよう、基準フレームは不動にする**（§4.5） |
| d | **XMP（crs: 名前空間）** | LensProfileEnable=1 等の初期設定を埋め込む（任意、ユーザーが選択） | 開いた時点でプロファイル補正がONになる |

- (c) のOpcode生成（メーカーノートからの変換）は機種ごとの解析が必要で、工数が大きい。そのため段階的に進める。
  1. **第1段階**：入力DNGのOpcodeListを引き継ぐ。
  2. **第2段階**：DNG Converterが利用可能なら、基準フレームを変換した「テンプレートDNG」から、Opcode・カラーマトリクス・UniqueCameraModel 等を丸ごと取得する。**精度が最も高い方式**。
  3. **第3段階**：主要機種について自前で変換する。
- **テンプレートDNG方式** はメタデータの正確性で非常に有利なので、第一候補として Phase 0 で検証する。ただし、古いmacOSでは新しいDNG Converterが動かない可能性がある【要検証：DNG Converter各版の動作OS】。そのため、自前でのメタデータ構築を必ずフォールバックとして残す。

### 6.4 書き出し後の検証

- DNG SDK付属の `dng_validate` で妥当性を検査する（CIに組み込む）。
- `exiftool -a -G1` で、DNG Converter出力とタグの差分を自動比較する（開発・テスト用。アプリには同梱しない）。

## 9. 開発フェーズとマイルストーン

> 最大の不確実性は「出力DNGが Lightroom Classic / Camera Raw で期待どおり扱われるか」にある。そのため **Phase 0でここを最初に潰す**。UIや合成アルゴリズムの作り込みは、その後に行う。

### Phase 0：実現性検証（最重要・最初に実施）

**目的**：出力DNGの仕様を確定させる。

0. **既存ツールの出力を解析する（最も安上がりな答え合わせ）**：
   - Lightroom Classic の「写真を結合 → HDR」の出力DNGと、HDRMergeの出力DNG（浮動小数点のCFA DNG）を用意する。
   - `exiftool -a -G1` と `dng_validate` で、WhiteLevel、値のスケール、BaselineExposure、プレディクタ、ビット深度、CFAかLinearRawか、を調べる。
   - HDRMergeの出力をLRで開き、AIノイズ除去・レンズプロファイル・カメラプロファイルが使えるかを確認する。コードを書く前に、浮動小数点CFA DNGの実用性を判断できる。
1. 実RAW 1枚をLibRawで読み、DNG SDKで **浮動小数点のCFA DNG** として書き直す（メタデータはコピー）。
2. 同じRAWを Adobe DNG Converter で変換したものと、LR Classic / ACR上で比較する。確認項目は次のとおり。
   - [ ] レンズプロファイルが自動認識されるか（EXIFコピーだけで足りるか）
   - [ ] カメラプロファイル一覧（Adobe Standard / Camera Matching）が出るか（UniqueCameraModel）
   - [ ] OpcodeList（組み込みレンズ補正）が適用されるか
   - [ ] AIノイズ除去 / 強化（Enhance）が浮動小数点CFA DNGで使えるか
   - [ ] 16/24/32bit floatの互換性と、表示の差
   - [ ] ハイライト（1.0超）が露光量やハイライトのスライダーで復元できるか
   - [ ] LinearRaw DNG（モードB）の場合に、上記がどう変わるか
3. `exiftool -a -G1` と `dng_validate` で、DNG Converter出力とのタグ差分を洗い出す。
4. テンプレートDNG方式（DNG Converterの出力を土台にして画像データだけ差し替える）の実現性を確かめる。
5. 10.13を配置ターゲットにしたUniversalビルドが、選定したXcode版で通ることを確認する。
6. **成果物**：出力DNG仕様書の確定版と、【要検証】項目の結論一覧。

### Phase 1：コアエンジン（CLI）

- RAW読み込み（LibRaw＋DNG）、黒レベル・白レベル処理
- 露出比のデータ推定、飽和判定

- CFA DNG書き出し（メタデータ、プレビュー、レンズ情報a・b）
- **マイルストーンM1**：三脚撮影の3/5/7枚ブラケットから、LRで違和感なく現像できるHDR DNGがCLIで得られる

### Phase 2：位置合わせ

- 自動位置合わせ（MTB→特徴点/ECC、チェーン方式）
- 出力モード A' / B の実装と画質比較 → 既定モードの決定
- DefaultCropによる無効域の処理
- **M2**：手持ちブラケットで破綻なく合成できる

### Phase 3：macOSアプリ（GUI）

- AppKitのUI：フレーム一覧、露出情報、プレビュー（簡易現像）
- 合成マップ・飽和警告・遷移帯の可視化、「滑らかさ」「飽和閾値」の調整
- 手動位置合わせUI（差分/オニオンスキン/フリッカー、ナッジ、回転、制御点）
- 非同期処理と進捗表示・キャンセル（GCD / NSOperation。async/awaitは使わない）
- **M3**：10.13〜最新のmacOSでGUIから一連の操作ができる

### Phase 4：品質強化

- ゴースト（動体）対策と、手動マスク修正
- 平均型の合成オプション
- OpcodeList：DNG Converterテンプレート方式の統合、主要機種での自前変換
- NoiseProfile の扱いの確定
- Metalによる高速化（任意）
- **M4**：ベータ版

### Phase 5：仕上げと配布

- **M5**：1.0リリース

## 12. ユーザーへの確認事項

方針に影響するため、以下を決めていただきたい。

1. **合成ルールの解釈**：§1.2の「飽和しない範囲で最も明るいフレームを使う」という原則でよいか。選択型を既定とし、平均型をオプションにすることでよいか。
2. **手持ち撮影の重要度**：三脚撮影が主か、手持ちも同等に重要か。手持ちの比重が高いと、CFA DNGを維持しにくくなる（§4.4）。
3. **配布形態**：直販（Developer ID＋公証）か、Mac App Storeか、両方か。
4. **ライセンス方針**：商用（クローズド）か、OSS（GPL可ならHDRMergeのコードを流用できる）か。
5. **優先するカメラメーカーと機種**：手元でテストできるRAWの機種。
6. **出力ビット深度**：ブラケット構成に応じた自動選択（§6.1）を既定とすることでよいか。それとも常に32bit floatに固定するか。
7. **UIの実装言語**：Swift（AppKit）か、Objective-Cか。開発者の習熟度による。
8. **Adobe DNG Converter への依存度**：インストールを前提にしてよいか（精度が最も高い）、あくまで任意とするか。
9. **性能目標**：想定する最大画素数と枚数、目標処理時間。

## 付録A：用語

| 用語 | 意味 |
|------|------|
| AEB | 自動露出ブラケット撮影 |
| CFA | カラーフィルタアレイ（Bayer、X-Trans等のモザイク配列） |
| LinearRaw | デモザイク済みだが、カメラネイティブ色空間の線形データを持つDNG |
| Opcode / OpcodeList | DNGに埋め込む処理命令（歪曲補正、周辺光量補正など） |
| BaselineExposure | DNG現像時の既定露出補正量 |
| MTB | Median Threshold Bitmap。露出差に頑健な位置合わせ手法 |
| ECC | Enhanced Correlation Coefficient。強度ベースの位置合わせ最適化 |
